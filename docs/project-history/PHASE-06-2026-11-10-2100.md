## 2. Yang dibangun

### 2.1 Server (`functions/api/sync.ts` + `src/sync/logika.ts`)

- `POST /api/sync` menerima batch kiriman; `GET` hanya balasan info layanan.
- **Idempoten** lewat tabel `sync_log` (`kunci = jenis:id:diubahPada`).
- Tiap kiriman divalidasi sendiri: satu rusak **tidak** membatalkan yang lain.
- Uang wajib integer; `total` pecahan ditolak.
- Tanpa `DB` binding → **503** (aplikasi tetap jalan).
- `SYNC_TOKEN` opsional lewat secret; tidak ada endpoint baca publik.

### 2.2 Skema D1 (`db/schema.sql`)

`transactions`, `transaction_items`, `payments`, `products`, `bazars`, `sync_log`.

## 5. Masalah terbuka / jujur

1. **Endpoint sinkronisasi BELUM diberi token** (`SYNC_TOKEN` kosong). Siapa pun yang tahu URL bisa mengirim data ke D1. Data hanya bisa **ditulis**, tidak bisa dibaca dari endpoint ini. Untuk butik kecil risikonya rendah, **tetapi sebaiknya diberi token**.
2. **Aplikasi belum mengirim otomatis penuh.** `VITE_SYNC_URL` belum diset saat build, sehingga `StatusSinkron` menampilkan "Tersimpan di perangkat" dan antrean menumpuk lokal. Pengiriman jalur nyata sudah saya buktikan manual; untuk otomatis perlu build ulang dengan `VITE_SYNC_URL=https://kasir-kayesha.pages.dev/api/sync`.
3. **Sinkronisasi satu arah** (perangkat → cloud). Belum ada tarik data dari cloud ke perangkat.
4. **Foto tidak disinkronkan** (keputusan: tanpa R2).
5. **D1 tidak diuji dengan data besar.**

## 6. Cara mengaktifkan sinkronisasi otomatis

```powershell
$env:VITE_SYNC_URL = "https://kasir-kayesha.pages.dev/api/sync"
npm run build
npx wrangler pages deploy dist --project-name kasir-kayesha
```

Menambah token (disarankan):

```powershell
npx wrangler pages secret put SYNC_TOKEN --project-name kasir-kayesha
$env:VITE_SYNC_TOKEN = "<nilai yang sama>"
```
