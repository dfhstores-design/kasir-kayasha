## 4. Bug & temuan nyata

| # | Temuan | Penyelesaian |
| --- | --- | --- |
| 1 | Ekspor menulis logo/foto sebagai **`{}`** karena `{...rec}` + `JSON.stringify` membuang Blob | Diolah lewat `keJsonAman` lalu base64 eksplisit |

| 4 | Penggantian regex saya sempat **merusak berkas tes** (method ganda) | Berkas tes ditulis ulang bersih; `tsc` menangkapnya |

## 5. Masalah terbuka / jujur

1. **Belum di-deploy.** Aplikasi hanya berjalan lokal (`vite preview`). Deploy ke
   Cloudflare Pages menunggu keputusan pemilik (akun, domain, izin).
2. **Foto & logo belum terbukti otomatis** lewat tes (batasan `fake-indexeddb`); buktinya
   hanya manual dan lewat unit test helper.
3. **Data hanya di satu perangkat.** Belum ada sinkronisasi (Phase 6). Bila HP rusak dan
   cadangan belum dibuat, data hilang — ini ditegaskan di panduan pemilik.
4. **Pemeriksaan aksesibilitas belum audit menyeluruh** (lihat Phase 3: ukuran huruf & tombol
   besar sudah diterapkan, `aria-pressed`/`role=alert` dipakai, tetapi belum ada audit formal).
5. **Uji performa data besar belum dilakukan** (belum ada 500+ barang/transaksi).
6. Printer thermal tetap *to be develop*.

## 7. Langkah deploy (saat pemilik setuju)

1. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Pilih `dfhstores-design/kasir-kayasha`, branch `main`.
3. Build command `npm run build`, output `dist`.
4. **Tidak perlu binding apa pun** untuk Phase 7 (semua data lokal).
5. Setelah selesai, buka alamat `https://kasir-kayasha.pages.dev` **di HP pemilik** dan
   ikuti `docs/PANDUAN-PEMILIK.md` bagian 1.

## 8. Tugas aman berikutnya

- Deploy hanya setelah pemilik menyetujui akun & alamat.
- **Jangan** mengaktifkan R2 tanpa persetujuan (subscription + metode pembayaran).
- Phase 6 (sinkronisasi D1/R2) baru setelah Phase 7 diuji di pameran nyata.
