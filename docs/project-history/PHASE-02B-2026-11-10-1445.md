## 1. Pemicu

Pemilik menegaskan aturan stok:

> stok gudang berkurang ketika dibawa ke bazar, stok bazar berkurang ketika terjadi penjualan,
> penjualan bazar tidak mengubah stok gudang

## 2. Temuan

Kode Phase 2 **sudah** berperilaku persis seperti itu (dibuktikan tes
`stok.test.ts > invarian stok bazar`), **tetapi ada celah penegakan**:

`simpanTransaksi` sebelumnya menerima array sumber stok bebas. Bila pemanggil keliru mengirim
`tipe: "gudang"` untuk transaksi yang berjalan di bazar, **stok gudang akan berkurang** dan aturan
pemilik dilanggar tanpa error.

Celah ini nyata: aturan yang hanya ada di dokumen akan mudah dilanggar pada Phase 3/3B saat UI
dibuat.

## 3. Yang dikerjakan

### 3.1 Modul aturan baru — `src/lib/sumberStok.ts`

Satu tempat yang menegakkan aturan, dipakai UI dan database:

| Fungsi | Tugas |
| --- | --- |
| `sumberStokUntuk(items, bazarId)` | Menyusun sumber stok: ada bazar → `bazar`, tidak ada → `gudang` |
| `validasiSumberStok(sumber, bazarId)` | Menolak kombinasi salah |
| `pesanStok(kode)` | Kalimat Bahasa Indonesia untuk pesan ke pengguna |

Kode kesalahan:

| Kode | Kapan |
| --- | --- |
| `penjualan_bazar_tidak_boleh_mengurangi_gudang` | Transaksi bazar mencoba memotong gudang |
| `tidak_ada_bazar_aktif` | Saldo bazar dipotong padahal tidak ada bazar / bazar berbeda |
| `saldo_bazar_tidak_cukup` | Penjualan melebihi saldo bazar |
| `stok_gudang_tidak_cukup` | Penjualan melebihi stok gudang |
| `jumlah_tidak_valid` | Kuantitas < 1 atau pecahan |

### 3.2 Repository sekarang MENOLAK pemanggilan salah

`simpanTransaksi` diperketat:

1. **Validasi bentuk** (`validasiSumberStok`) sebelum apa pun ditulis.
2. **Validasi kecukupan** stok gudang/saldo bazar sebelum menulis.
3. Baru kemudian menulis transaksi, item, pembayaran, dan mengurangi stok.

Karena semua pemeriksaan terjadi sebelum penulisan, pemanggilan yang salah **tidak meninggalkan
perubahan sebagian**. Parameter `stokBaru` kini bertipe `readonly SumberStok[]`.

### 3.3 Tes baru

| Berkas | Jumlah | Isi |
| --- | --- | --- |
| `src/lib/sumberStok.test.ts` | 7 | Penyusunan sumber & penolakan kombinasi salah |
| `src/db/alurStok.test.ts` | 7 | End-to-end lewat IndexedDB |

Isi tes end-to-end (masing-masing benar-benar dijalankan):

1. **(1) Gudang 40 → dibawa 10 → gudang 30, bazar 10.**
2. **(2) Jual 3 dari bazar → bazar 7.**
3. **(3) Jual 5 → stok gudang tetap sama** (dibanding sebelum penjualan).
4. Repository **menolak** penjualan bazar yang memakai `tipe: "gudang"` → error
   *"hanya mengurangi stok bazar"*, stok tidak berubah.
5. Repository **menolak** penjualan melebihi saldo bazar → error, stok tidak berubah.
6. Penjualan di luar bazar mengurangi **gudang** (40→26 setelah alokasi 10), bazar tetap 10.
7. Setelah jual 3 dari 10: gudang 30, sisa bazar 7 (siap dikembalikan saat tutup).

## 6. Catatan untuk agent berikutnya (PENTING)

- **Jangan** mengurangi `products.stokGudang` saat menjual barang bazar.
- Saat membuat transaksi, **selalu** pakai `sumberStokUntuk(items, bazarId)`; jangan menyusun
  array sumber stok sendiri.
- Bila menemukan kode yang memanggil `simpanTransaksi` dengan `tipe: "gudang"` padahal transaksi
  punya `bazarId`, itu **bug** — perbaiki pemanggilnya, jangan melemahkan validasinya.
- Tes `src/db/alurStok.test.ts` adalah pengunci aturan ini. Jangan menghapus atau melemahkannya.
