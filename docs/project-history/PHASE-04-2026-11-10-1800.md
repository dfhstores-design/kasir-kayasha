## 1. Tujuan

1. Pre-order: pemesan, kontak, perkiraan siap, alamat, catatan.
2. **DP dan pelunasan bertahap**; status pembayaran terpisah dari status pesanan.
3. Status pesanan: Diproses → Siap → Selesai / Dibatalkan.
4. **Ongkir menyusul** (`belum_ditentukan`) dapat diisi kemudian, total dihitung ulang.
5. Pembatalan tidak menghapus pembayaran.

## 2. Aturan paling penting (dikunci dengan tes)

| Aturan | Bukti |
| --- | --- |
| **PO TIDAK mengurangi stok saat dibuat** | `stokBaru: []` di `simpanPO`; 2 tes menjaga |
| **Stok berkurang saat PO berstatus SELESAI** | `ubahStatusPesanan` memanggil `simpanTransaksi` dengan sumber stok |
| Pembayaran melebihi sisa **ditolak** | `hitungPembayaranBaru` + 5 tes |
| Ongkir menyusul: total dihitung ulang, **riwayat tercatat** | `hitungIsiOngkir` + `riwayatTotal` |
| **LUNAS bisa berubah jadi DP** saat ongkir ditambah | 1 tes khusus |
| Pembatalan **tidak menghapus** pembayaran | 4 tes |
| Status final tidak bisa berubah (selesai/dibatalkan) | `transisiSah` + 1 tes |

## 6. Masalah terbuka / jujur

1. **Tombol "Lihat Resi" masih penanda** (membuka Pengaturan). Resi PDF = Phase 5.
2. Pembatalan **belum mengubah status pembayaran** menjadi "dikembalikan"; uang DP tetap tercatat
   sebagai sudah dibayar. Aturan refund tercatat belum dibuat.
3. PO dari gudang (bukan bazar) **tidak mengurangi stok saat dibuat** — barang dijanjikan walau
   stok gudang kurang. Validasi ketersediaan PO belum ada.
4. `totalSisaPO` memakai seluruh PO; belum dipisah per hari.
5. Ringkasan (Phase 3C) belum memisahkan omzet PO vs penjualan langsung.

## 7. Cara melanjutkan

1. Baca catatan ini + `docs/design/screens/07-pesanan.md` & `08-pesanan-detail.md`.
2. **Phase 5**: profil usaha, logo, rekening, resi PDF (susunan di
   `docs/design/BAZAR-PARKIR-RESI.md` bagian 5), berbagi, dan tombol "Lihat Resi" yang benar.
3. Saat menambah field transaksi, perbarui `simpanPenjualan`, `simpanPO`, dan fixture tes.
4. Jalankan lint + typecheck + test + build; catat hasil sebenarnya.
